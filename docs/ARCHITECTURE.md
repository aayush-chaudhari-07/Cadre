# ARCHITECTURE: Cadre

## 1. Overview
```
Browser (React SPA, static files on Cloudflare Pages)
   │  supabase-js (publishable key, user JWT)
   ├──────────────► Supabase Auth ───────────────┐
   ├──────────────► Postgres (RLS on every table) │  same user session
   └──► Edge Functions (Deno) ◄───────────────────┘
            │  verifies JWT, checks daily quota, validates input (Zod)
            └──► Gemini API (GEMINI_API_KEY secret, never in the browser)
```
Everything is free-tier friendly: static hosting, one Supabase project, one Gemini key.

## 2. Stack
| Layer | Choice | Why |
|---|---|---|
| Language | TypeScript (strict) | Safety |
| UI | React 19 | Keeps the existing component knowledge |
| Build | Vite | Standard, fast, no vendor plugins |
| Routing | TanStack Router (file-based, SPA mode) | Typed routes, route guards via `beforeLoad` |
| Server state | TanStack Query | Caching, loading and error states |
| Styling | Tailwind CSS v4 + CSS variables | Tokens from `DESIGN.md` |
| Motion | `motion`, `lenis` (landing only) | See `DESIGN.md` |
| Charts | Recharts | Already familiar, easy to theme |
| Forms | React Hook Form + Zod | Validation on client and server |
| UI primitives | Radix UI via shadcn-style components | Accessible, only the pieces used |
| Icons | lucide-react | Already used |
| Backend | Supabase (Auth, Postgres, Edge Functions) | One free service for all three |
| AI | Google Gemini via `@google/genai` in Edge Functions | Free tier for Flash models |
| Tests | Vitest + Testing Library, Playwright for 3 smoke flows | Enough confidence |
| Hosting | Cloudflare Pages (frontend), Supabase (backend) | Free and allowed for commercial use |
| CI | GitHub Actions | Free |

Pin exact versions in `package.json` at install time (use the latest stable, not betas).

## 3. Decisions
| Decision | Reason |
|---|---|
| **SPA instead of SSR** | The old build used a beta server runtime tied to a vendor config. A static SPA deploys anywhere for free. Landing SEO is handled by static `<head>` tags, OG tags and JSON-LD. Pre-rendering `/` and `/pricing` is a roadmap item. |
| **Gemini only in Edge Functions** | Keeps the key secret and lets us enforce quota, validation and logging in one place. |
| **Drop Drizzle, use SQL migrations** | The DB is Supabase; plain SQL migrations with RLS are the simplest source of truth. Types are generated with `supabase gen types`. |
| **New Supabase project** | The old project was provisioned and managed by the old app builder. Create your own so you own the keys, data and dashboard. |
| **npm, not bun** | Works on every machine and CI runner. |
| **Cloudflare Pages, not Vercel Hobby** | Vercel's free Hobby plan is limited to non-commercial use. Re-check each provider's terms before launch. |
| **Forecast numbers computed in code** | The model writes the explanation only. Numbers are never generated by AI. |

## 5. Auth and routing
- `AuthProvider` in `src/features/auth` holds the Supabase session via `onAuthStateChange` and exposes `useAuth()`.
- `/app` route `beforeLoad`: if no session, redirect to `/login?redirect=<path>`. If session but no membership, redirect to `/onboarding`.
- Active workspace = the user's first membership (v1). Stored in a `WorkspaceProvider` and used in every query key (`['leads', orgId]`).
- Auth pages redirect signed-in users to `/app`.
- Google OAuth uses `supabase.auth.signInWithOAuth({ provider: 'google', options: { redirectTo } })`.

## 6. Data access
- Reads and simple writes go straight from the browser to Postgres through supabase-js; RLS enforces access.
- AI actions go through Edge Functions. The browser never calls Gemini.
- Each feature folder has `api.ts` (supabase calls), `hooks.ts` (TanStack Query hooks) and `schemas.ts` (Zod).
- Query keys always include `orgId`. Mutations invalidate the narrowest key possible.
- Money is stored as `numeric(12,2)` and formatted with `Intl.NumberFormat('en-US', { style: 'currency', currency: 'USD' })`.

## 7. Edge Function contract
**Request:** `POST /functions/v1/<name>` with `Authorization: Bearer <user JWT>` and a JSON body validated by Zod. Every body includes `orgId`.

**Steps in every function**
1. Handle CORS (`ALLOWED_ORIGINS` allowlist) and `OPTIONS`.
2. Create a user-scoped Supabase client from the `Authorization` header; `getUser()` must succeed.
3. Confirm the user is a member of `orgId` (a read through RLS is enough).
4. Validate the body (Zod). Reject oversized input.
5. Call `consume_ai_quota(AI_DAILY_LIMIT_PER_USER)`; if false return `429 { error: { code: "quota_exceeded" } }`.
6. Call Gemini with the module's system prompt and a JSON response schema. Try `GEMINI_MODEL`, fall back to `GEMINI_FALLBACK_MODEL` on 429/503.
7. Validate Gemini's JSON with Zod. On failure, retry once, then return `502 { error: { code: "bad_model_output" } }`.
8. Save results through the user-scoped client (RLS applies), write an `agent_runs` row, return the result.

**Errors** always look like `{ "error": { "code": "...", "message": "..." } }` with codes: `unauthorized`, `forbidden`, `invalid_input`, `quota_exceeded`, `bad_model_output`, `upstream_unavailable`, `blocked_url`.

**Client:** `src/lib/ai.ts` wraps `supabase.functions.invoke`, maps error codes to friendly messages, and exposes typed helpers (`analyzeLead`, `analyzeMeeting`, ...).

## 8. Gemini usage
- SDK: `npm:@google/genai` inside Deno.
- Use `responseMimeType: "application/json"` plus a response schema per module.
- Temperature 0.3 for analysis, 0.6 for the CEO plan.
- Cap input size (see schema limits in the SQL) and output tokens (about 1,500).
- Cache: daily insights are stored per workspace per day; competitor scans store the analysis; meeting and lead analyses are stored on their rows. Never re-call the model to display something already saved.
- The model name is configuration, not code. Check Google AI Studio for which Flash or Flash-Lite model is currently free for your project and set `GEMINI_MODEL`.

## 9. Competitor scan fetching
The function fetches the URL itself. It must: allow only `http`/`https`, resolve DNS and block private, loopback and link-local addresses, follow at most 3 redirects (re-checking each), time out at 8s, read at most 500KB, strip scripts and styles, and keep the first ~12,000 characters of visible text. See `SECURITY.md`.

## 12. Testing
- **Unit (Vitest):** formatters, CSV parser, forecast calculations, Zod schemas, `ai.ts` error mapping.
- **Component:** auth forms, lead table filtering, AI result panel states.
- **E2E (Playwright, 3 flows):** sign up then onboarding then sample data; login then analyze a lead (mock the function); logged-out redirect.
- **SQL check:** a script that signs in as two different users and proves neither can read the other's rows.
