# LEGACY CLEANUP: remove every trace of Lovable and FlowMind

The old app was generated by Lovable and its backend was provisioned through Lovable Cloud. Cadre must not depend on any of it. This list comes from the project audit.

## 1. Strategy
1. Make a backup zip of the whole folder first (outside the project).
2. Run `git init` (the old folder had no git history) and commit the untouched project on a branch called `legacy-snapshot`.
3. Create branch `rebuild`. Move the old `src/` to `legacy/src/` for reference only (excluded from lint, TypeScript and build).
4. Run `scripts/purge-legacy.ps1` (dry run), read the output, then run it with `-Apply`.
5. Rebuild the app from the new scaffold, copying ideas (not code) from `legacy/` when useful.
6. In the final prompt, delete `legacy/` and run the verification commands in section 5.

## 2. Files and folders to delete
| Path | What it is |
|---|---|
| `.lovable/` | Project metadata for the builder |
| `bunfig.toml`, `bun.lock`, `bun.lockb` | Bun config with builder package allowlist |
| `src/integrations/lovable/` | Builder OAuth helper |
| `src/lib/lovable-error-reporting.ts` | Builder error telemetry |
| `src/integrations/supabase/previewAuthStorage.ts` | Builder iframe auth sync |
| `src/integrations/supabase/auth-attacher.ts`, `auth-middleware.ts`, `client.server.ts`, `cron-auth.ts` | Server glue tied to the old setup and an unused service-role client |
| `drizzle/`, `drizzle.config.ts` | Empty ORM scaffold (we use SQL migrations) |
| `supabase/config.toml` (old) | Points at the old managed project; regenerate with `supabase init` |
| `roadmap.md` (old) | Old auth checklist; replaced by `docs/ROADMAP.md` |
| Old `README.md`, old `AGENTS.md` | Replaced by the new ones |
| `src/routeTree.gen.ts` | Regenerated by the router plugin |
| `.env` | Contains keys for the old managed backend. Delete it and never reuse those keys |

## 3. Packages to remove from `package.json`
- `@lovable.dev/vite-tanstack-config`
- `@lovable.dev/cloud-auth-js`
- Any `@lovable.dev/*` entry, including the dev-server bridge and HMR gate plugins
- `@tanstack/react-start`, `nitro`, and anything else used only for the old SSR setup
- `drizzle-orm`, `drizzle-kit`, `postgres`
- Unused UI packages (only keep the Radix packages the new UI actually imports)

Also rename the package from `tanstack_start_ts` to `cadre`.

## 4. Strings to search for and remove
Search every file outside `node_modules`, `.git` and `legacy/` for these (case-insensitive):

| Pattern | Where it appeared |
|---|---|
| `lovable` | Config, README, AGENTS.md, env vars (`LOVABLE_CRON_SECRET`, `LOVABLE_DB_MIGRATION_URL`), preview origins |
| `gptengineer` | Older builder name sometimes left in meta tags |
| `flowmind` | App name, storage key `flowmind.session-mode`, README |
| `tanstack_start_ts` | Old package name |
| `r2.dev` | The hard-coded social preview image URL |
| `id-preview` | Preview domain pieces in meta tags |
| `Alex Morgan`, `Acme Inc` | Hard-coded demo user and company |

## 5. Backend note: create your own Supabase project
The old database and auth project belonged to the builder's managed cloud, so you may not have full dashboard access or the service keys. Do not try to reuse it.
1. Create a new Supabase project under your own account.
2. Run `supabase/migrations/0001_init.sql`.
3. Use only the new URL and keys. If you want any old user data, export it from the old project first; there was only a `profiles` table and no business data.

## 6. Verification commands (all must print nothing)
PowerShell:
```powershell
Get-ChildItem -Recurse -File -Force |
  Where-Object { $_.FullName -notmatch 'node_modules|\\\.git\\|\\docs\\|\\scripts\\' } |
  Select-String -Pattern 'lovable','gptengineer','flowmind','r2.dev' -List
```
Git Bash / macOS / Linux:
```bash
grep -rIil --exclude-dir=node_modules --exclude-dir=.git --exclude-dir=docs --exclude-dir=scripts \
  --exclude=ci.yml -e lovable -e gptengineer -e flowmind -e "r2.dev" .
```
Also check:
- `package.json` and `package-lock.json` contain no `@lovable.dev` entries
- `dist/` (after `npm run build`) contains none of those strings
- Browser tab shows the Cadre favicon and title, and the Network tab shows no request to any builder domain
- Page source `<head>` has your own OG image on your own domain
- Supabase Site URL and redirect URLs list only your domains

## 7. What to keep in spirit (as ideas, rewritten)
The old app's module list (Command Center, Leads, Revenue, Churn, Meetings, Competitors, Agents, Insights, AI CEO, Settings) and its overall information layout are kept. All code, styling and copy are rewritten.
